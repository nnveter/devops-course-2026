# Подготовка к КР №1

## Когда rebase, а когда merge?
Rebase — для своей локальной (ещё не опубликованной) feature-ветки: подтянуть свежий main и получить линейную историю без лишних merge-коммитов. Merge — для интеграции в общую ветку (main) и для любых веток, с которыми уже работают другие: история не переписывается, видно, где шла параллельная разработка.

## Что будет, если сделать rebase публичной ветки?
Все коммиты ветки получат новые хеши. У коллег останутся старые коммиты; при следующем pull Git попытается объединить две версии одной и той же работы — появятся дубли коммитов и конфликты, а push без --force будет отклонён. Если кто-то сделает force push, чужие коммиты могут быть потеряны.

## Зачем нужен multi-remote?
Резервное зеркало (GitHub + GitLab/GitVerse) на случай недоступности или блокировки площадки; работа с форком (origin — свой форк, upstream — оригинал); выкладка в разные окружения (например, отдельный remote для деплой-сервера или корпоративного GitLab).
